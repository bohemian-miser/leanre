# Virtual Proof Stripper (`leanre trim`)

> **Scope:** `leanre/trim.py` computes read-only size reductions over pinned commit `40e56bab` (`175,187` files, `17,374,215` lines) and `outputs/kernel/kernel.db` (`1,468,418` folded records / `1,484,733` unpacked constants from `solution.ndjson.zst`, SHA-256 `5ea74b91…244e`). It does not re-elaborate `.lean` files or evaluate mathematical validity.

## Quickstart

```bash
# Instant waterfall table from the saved report (< 50 ms)
python3 leanre/leanre.py trim --from-report outputs/decomp/trim_report.json

# Full read-only recomputation across 175,187 files + kernel.db + tier1.db (~37 s)
python3 leanre/leanre.py trim --out outputs/decomp/trim_report.json --workers 16

# Synthetic + real-report conservation unit tests
python3 -m unittest leanre/test_trim.py -v
```

## Bloat mechanisms

1. **Unused zero-kernel modules** — Of `28,904` zero-kernel `.lean` files, `19` (`1,631` lines) are live alignment-gap modules kept inside the `146,302` set. The remaining `28,885` (`2,376,906` lines, `143,500,521` B) split into `28,471` imported-but-unused files (`2,358,861` lines, including [dead `DyadicPrimeIntervals` checks](https://github.com/leanprover-community/riemann-hypothesis/blob/40e56bab026552e089d7afcfeff08d2defb9c005/src/Formalism/PeriodIntegrals/UnitaryGroupMassFormula/DyadicPrimeIntervals/Run1.lean#L6)), `239` unused private/struct/abbrev/instance files (`16,838` lines), `164` pure import/scope shims (`959` lines), and `11` kernel-erased meta/attribute files (`248` lines).
2. **Dead declarations in live files** — `115,829` declarations across `17,984` live modules never enter `solution.ndjson.zst` (`115,822` in the `146,283` mapped modules; `1,089,514` block / `979,578` non-blank lines: `69,044` `theorem`, `36,873` `def`, `3,345` `example`, `2,592` `lemma`, `1,656` `abbrev`, `1,281` `structure`, `1,023` `instance`, `14` `inductive`, `1` `class`). Extreme outliers include [`OscillatoryIntegralBounds`](https://github.com/leanprover-community/riemann-hypothesis/blob/40e56bab026552e089d7afcfeff08d2defb9c005/src/Formalism/SharpRestriction/CuspSpanNormBounds/OscillatoryIntegralBounds.lean#L38) (`515` dead vs `17` live; `5,459 / 6,333` lines dead) and [`HeisenbergConjugationMeasurePreserving`](https://github.com/leanprover-community/riemann-hypothesis/blob/40e56bab026552e089d7afcfeff08d2defb9c005/src/Formalism/HermitianCurvature/HeisenbergConjugationMeasurePreserving.lean#L374) (`1,416` dead re-exports vs `102` live).
3. **Single-node forwarding aliases** — Every live `value_nodes == 1` declaration (`44,124` total, including `863` external library entries) has a single value edge (`fan_out_value == 1`). 4. **Duplicate imports and shims** — The corpus carries `19,750` duplicate `import Mathlib` lines and `308` duplicate project imports (`150` strict / `164` total shims). ## Limits

- `1,656` of the `115,829` kernel-absent declarations inside live files are `abbrev`s that may unfold during elaboration without leaving a constant in `solution.ndjson.zst`. Two of the `11` zero-kernel meta files (`CutCptCopy` and `HeckeNonvanishing.Imports`) also execute during elaboration for live callers.
- Signature-abstracted (`s1a`) clone sets stay outside the waterfall because `s1a` abstracts project-local identifiers ([signature hashing](SIGHASH.md)), and equal `k1n` on `def`s (`51,500` collisions) means equal type rather than equal body. Step 4b deduplicates only `Prop`-valued `thm`s, where earliest-`decl_id` substitution preserves topological acyclicity (`dst < src`).
